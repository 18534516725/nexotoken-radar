# Radar 多维检测、历史、开放 API 与评分榜单补充规格

## 目标

将现有三项兼容性检查升级为按协议、模型能力和目标工具动态编排的检测系统，并以同一标准化结果驱动即时报告、可选公开历史、开放 API 和可信榜单。

## 输入与端点发现

用户可输入域名、带协议的域名或完整 Base URL。系统仅在同一主机内规范化路径：OpenAI Responses 使用 `/v1/responses`，Chat Completions 使用 `/v1/chat/completions`，Anthropic Messages 使用 `/v1/messages`。运行前必须展示最终端点；高级用户可显式覆盖路径。禁止跟随重定向、切换主机或访问私网地址。

## 检测模式

- 快速检测：3-6 个请求，覆盖连接、鉴权、模型访问、流式与工具调用。
- 完整检测：15-35 个请求，增加错误脱敏、参数遵从、用量完整性、延迟抖动、多轮稳定性、结构化输出及模型支持的专项能力。
- 所有请求限制时间、响应大小、输出 token 和并发；运行前显示预计请求数与可能消耗。

## 动态矩阵

公共维度包括连接、鉴权、模型访问、错误规范、流式完整性、延迟、抖动、用量、输出限制、限流、多轮稳定性。Responses、Chat Completions 和 Anthropic Messages 分别验证其事件序列、工具格式和协议字段。推理、工具、视觉、长上下文、缓存、JSON Schema、logprobs 等能力只在适用时执行；不适用项为 N/A，不计零分。

模型身份、自报名称、tokenizer 差异和响应头只能作为弱证据，不能单独断言真假模型。内部可以记录脱敏的链路类别，但公开页面不得展示上游供应商、内部渠道标识、原始错误或凭证。

## 评分

即时报告展示综合分、覆盖率、可信度和有效探针数。综合分按实际适用维度重新归一化；覆盖率独立显示，防止少测项目获得虚高分。正式榜单只纳入用户主动公开、满足至少 20 次近期有效观测且达到最低覆盖率的结果。一次检测不得形成长期可靠性结论。

## 历史、报告与 API

凭证、提示正文和原始响应不落库。用户选择公开后才保存脱敏摘要并生成不可猜测的报告 ID；公开结果可撤销。开放 API 第一阶段只读，提供供应商、模型、榜单、公开报告和检测历史端点，并执行限流与缓存。

## 发布阶段

1. 检测核心与即时报告：无需数据库变更。
2. 历史、公开报告和开放 API：执行审核后的 `radar_` 数据库迁移。
3. 聚合任务和榜单：累计达到样本门槛后开放正式排序。
